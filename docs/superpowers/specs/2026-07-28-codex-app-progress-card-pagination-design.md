# Codex App 进度卡分页设计

## 目标

大型任务持续产生进展时，单张飞书卡片不能无限增长。达到页面阈值后冻结旧卡并创建新卡继续更新，同时在飞书内保留完整、按时间排序的处理过程。

## 分页规则

- 每张卡片最多承载 8 个内容块或 1800 个字符，任一阈值先到即在下一条内容写入前换页。
- 内容块包括首条确认、每条完整 assistant 进展和终态；只在内容块边界分页，不拆分句子或段落。
- 单个内容块本身超过 1800 字时独占一页，不截断内容。
- 第一页从“已收到，开始处理”开始；后续页直接从触发换页的新进展开始，不重复首条确认。

## 卡片状态

- 当前页标题使用 `处理中 · <任务摘要>（进度 N）`；完成、失败和中断沿用现有颜色与终态前缀。
- 换页成功后，旧页 PATCH 为灰色 `进度 N · 已归档 · <任务摘要>`，内容不再改变。
- 任务终态只更新最后一页；所有历史页保持灰色归档状态。
- 会话状态新增页码、当前页内容块数和归档页列表。每个归档页保存页码、消息 ID、内容和归档 PATCH 是否成功，daemon 重启后可以继续补齐未完成操作。
- 现有单页状态自动视为第 1 页，按已有时间戳边界推导内容块数，不要求迁移脚本。

## 写入和失败恢复

所有状态变更继续经过当前串行队列：

1. 新内容触发分页时，先把旧页写入归档列表，再建立没有消息 ID 的新当前页并持久化。
2. 先 POST 新当前页，保证最新进展优先可见；POST 失败时保留待发送页，下一次同步重试，不丢内容。
3. 新页可见后 PATCH 旧页为灰色归档；PATCH 失败保留未同步标记，后续更新继续重试。
4. 旧归档卡已被撤回时不补发；当前页被撤回时沿用现有“最多补发一次”规则。
5. 分页、归档或补发失败只记录并重试，不阻塞 Codex 消息派发和最终答案通道。

## 测试与验收

- 第 8 个内容块仍在第 1 页，第 9 个内容块创建第 2 页。
- 追加内容导致总字符超过 1800 时创建新页。
- 单条超长内容完整保存在独立页。
- 新页 POST 成功后旧页变为灰色归档，终态只更新最新页。
- 新页 POST 失败后状态可恢复；归档 PATCH 失败不会阻止当前页继续展示。
- daemon 从旧单页状态和新分页状态恢复后都能继续正确页码。
- 现有即时创建、时间戳、steer、去重、终态和撤回补发行为保持不变。
